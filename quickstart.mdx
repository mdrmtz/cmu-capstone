**The A11y Fixer** automates WCAG 2.2 AA remediation in Angular codebases. It takes an `axe-core` audit report as input and delivers a verified, regression-free Pull Request as output — no manual code editing required.

## How it works in three steps

<Steps>
  <Step title="Audit — detect violations">
    Run `axe-core` against your Angular app to generate a structured JSON violation report. The A11y Fixer reads this report to identify the failing DOM node, its CSS selector, and the specific WCAG criterion it violates.

    ```bash
    npx axe --save audit.json https://localhost:4200
    ```
  </Step>
  <Step title="Retrieve — fetch authoritative context">
    The **Compliance Planner Agent** routes each violation through the Hybrid RAG pipeline:

    - **Known `axe-core` error codes** (e.g. `button-name`, `color-contrast`) → deterministic LLM Wiki lookup — zero vector search, zero hallucination risk
    - **Exploratory queries** → Stateless Semantic Search with MMR reranking (λ=0.5, k=3 diverse chunks)

    Output: a structured compliance manifest with exact ARIA attributes, Angular template patterns, and remediation constraints.
  </Step>
  <Step title="Remediate — patch, verify, and deliver">
    The **Codebase Compiler Agent** applies Tree-of-Thought DFS search (k=3 branches, depth T=3) to generate candidate AST patches. Each patch is scored by the **QA Critic Agent** on a 0–20 rubric:

    | Metric | Weight |
    |---|---|
    | Angular Ivy compile safety | 8 pts |
    | AST structural validity | 4 pts |
    | WCAG semantic compliance | 5 pts |
    | Visual layout stability (≤2% shift) | 3 pts |

    Patches scoring >5 with clean compilation are merged into a Pull Request. Patches scoring ≤5 trigger Adaptive Sibling Inflation (k→5) and contrastive backtracking.
  </Step>
</Steps>

## Key concepts

| Term | Meaning |
|---|---|
| `axe-core` | Open-source accessibility auditing engine — produces the violation report the agent consumes |
| LLM Wiki | Deterministic, pre-vetted markdown registry indexed by `axe-core` error code |
| Stateless Semantic Search | Stateless vector RAG — identical queries always return identical chunks |
| Tree-of-Thought (ToT) | Search strategy that proposes, evaluates, and backtracks across k=3 AST patch branches |
| Angular Ivy compiler | The compilation target used to validate every patch before scoring |
| Git transactional sandbox | Each ToT branch runs in a pristine workspace (`git checkout -f && git clean -fd`) |
